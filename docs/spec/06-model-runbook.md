# 06 · 低模型执行手册与提示词

目的：让执行模型一次处理一张小任务卡，减少上下文、猜测和返工。T00—T32是父任务，复杂任务按卡内a/b/c子步骤逐个交付；不得把整个v2项目一次性交给模型自由重写。

## 1. 执行前固定输入

每次仅提供：00的固定决策/阶段表、当前任务卡、卡点名的规格章节、实际仓库AGENTS.md、相关接口文件与对应fixture。读取git status与现有实现后再改；不得用安装包目录代替源码仓库。

T00初始化`docs/progress.json`：任务状态`not_started/in_progress/review/accepted/blocked`、commit、证据文件、未完成gate；初值全部not_started。依赖仅当accepted且明确指定的前置gate通过才算满足；本阶段内部任务不等待由后续任务形成的整阶段gate，不能制造T06等待G1等循环。规划文件存在不代表实现已完成。

所有任务共有docs/progress.json、docs/evidence/Txx/**与tests/tasks/Txx/**的本卡权限，manifest/card列出同样路径。T06建立编译骨架和锁文件，后续新增依赖须另开受审查T06依赖子卡；补列的包入口仅做本模块export/registration，不扩大业务权限。测试若需新增入口在既有根脚本中发现本卡测试目录；不得修改无关模块以绕开约束。

低模型单次修改建议上限：生产代码<=400行、<=5个手写文件；测试/fixture另列。超过时先拆为同一任务的a/b子卡，每个都有可运行结果；不能删掉要求以满足行数。通用生成文件、lockfile只在指定生成/依赖任务允许变更。

## 2. 每张卡的执行步骤

1. 确认仓库路径、任务依赖、测试profile和允许修改路径；查看同名模块是否已有实现。
2. 列出本次最小交付与先失败的关键fixture。可复用现有成熟库，不自造通用框架；新增库先检查stars/半年更新/稳定版本/许可证。
3. 先实现边界与错误结果，再接正常流程。外部服务用fake transport或隔离测试环境，不碰生产账号/桶/历史。
4. 只在允许目录实现；UI任务通过fixture adapter，不夹带数据库/加密/支付改动。跨文件生成按canonical contract运行，不手改generated。
5. 跑卡内必要检查：针对性用例→类型/边界→必要集成。失败记录最小复现，不重复全量构建碰运气。iOS原生变化/阶段gate才完整构建，日常以JS/fixture/静态校验为主。
6. 检查diff、秘密/正文日志、容量/取消/错误分支。关键任务交独立审查agent，修复审查项后只重跑受影响检查。
7. 用规定格式交付，更新progress为review；只有验收负责人有证据确认后accepted。用户授权提交Git时写中文日志。

Routine choices按既定spec继续，不为命名/布局细节停工；冻结协议冲突、平台API缺能力、生产凭据或真实用户数据操作等不能猜。保存可运行部分、失败证据、最小待决策项，禁止假成功或回退到明文/越权模式。

## 3. 可直接复制的单任务提示词

```text
你负责 ClipNest 的任务 {Txx}，只实施该任务当前子卡。
仓库：{D:\ClipNest-work\electron-l0 或 D:\ClipNest-work\v2}。
先读取仓库AGENTS.md、docs/progress.json、规划00的固定决策、06执行手册、
tasks/{Txx}.md，以及卡点名的规格章节和fixture。

依赖必须accepted；若未满足，完成不依赖它的fixture/接口草案并准确记录，
不要接入假成功后端，也不要继续执行后续卡。

按任务卡的允许路径实现。每次<=5个手写生产文件/约400行生产diff；
更大任务拆a/b子卡，不省略功能。禁止安装目录、真实用户历史、生产服务变更。
包管理pnpm，Rust用Cargo；不得常规升级依赖、手改generated或扩大限额。
遵循03/04冻结协议，不修改AAD/nonce/RLS/seq/删除语义/取消边界。

先指出正常、错误与取消fixture，再做最小实现，运行卡指定检查。
测试以可观察行为为准，不写与实现一模一样的镜像逻辑。
Windows自动输入仅在受控测试窗口和合成内容的测试范围执行；
不向当前用户工作窗口发送键、抢焦点或改剪贴板。

完成后输出：改了什么、文件、实际命令与结果、证据路径、未通过项、回滚方式。
未运行就写未运行。不要承诺已完成整个v2。进度先置review，等独立验收。
```

## 4. UI专用提示补充

```text
按01的指定页面层级和冻结交互实现，使用现有tokens与fixture adapter。
覆盖loading/empty/no-results/offline/locked/error/quota/permission/conflict状态。
输入法composition、重复Enter、单击选中/双击一次执行、迟到query结果必须验证。
组件不直接访问Tauri、数据库、文件、S3或billing；上层adapter调度一次。
只绘制有限摘要与thumbnailRef，不把原图Base64/全文放入每张卡。
完成浏览器可验证流程；真机尚未测就说明，不用截图替代原生权限验收。
```

## 5. 独立对抗审查提示词

```text
只读审查任务{Txx}的diff与证据，不先改代码。
尝试推翻其完成结论：从用户动作、断网/乱序/重复/取消/崩溃/越权/容量满出发。
核对任务DoD与03/04冻结边界，重点找数据丢失、复活、错目标输入、
跨账号泄露、账本少计、密钥恢复失败、假P95、仅mock通过。
指出具体文件/行、触发步骤、影响、最小修复与必要回归；没有证据不要虚构问题。
严重问题未解决不能accepted；不要为美化代码扩大范围。
```

## 6. 必须独立审查的卡

T02/T03/T05原生输入；T07/T08数据库与迁移；T14—T19认证/密码/同步/附件；T23/T24移动钥匙/同步；T25跨端；T26—T29权益/支付/删除；T30/T31发布。

低模型可以按已有规格实现绑定和fixture，但不能自行批准密码协议、RLS关闭、生产账本迁移、删除回收或真实发布。需要模块负责人/独立agent给出可审查结论；这不是要求每个小改动都重新征求用户确认。

## 7. 完成结果模板

```text
任务：Txx / 子卡a
结果：完成当前子卡 / 有阻断（原因）
行为：一个具体前后例子
文件：实际修改清单
验证：命令、exit结果、fixture、受控环境；未运行项目
预算：影响的队列/字节/并发与测量边界
证据：docs/evidence/Txx/（脱敏JSON/截图/测试报告）
风险与限制：目标应用真实处理、平台未测等
回滚：feature flag/commit/备份与数据格式兼容说明
进度：review；下一子卡/后续依赖不自动执行
```

## 8. 约束与停止条件

- 禁止通过增加sleep、关闭断言、跳过失败测试、关闭RLS、service-role全表访问、明文fallback取得绿色结果。
- 不能把SendInput ACK、HTTP200、单独组件中位数、mock支付或Web截图当真实完成/平台P95/订阅生效证据。
- 对未知结果只做幂等核对；自动重试不得造成重复输入、重复收费或多份附件。
- 不能修改系统HOME/CODEX_HOME等变量；任务变量另命名。Windows文件操作使用LiteralPath并先验证绝对目标位于任务目录。
- 编码时若karpathy-guidelines技能实际可用则读取；未安装记录即可，不假装已用，也不为规划安装额外插件。
- 本规划任务不授权生产部署、外部消息或修改用户真实内容。实际发布在当时用户授权下，先生成可审查artifact与staging证据。

## 9. 防止上下文遗失

每次接受子卡把接口版本、错误码、fixture和证据提交仓库；后续从progress与文件恢复，不依赖聊天记忆。大型03不必全读：卡里指定章节；遇相关状态机边界再补读相邻章节。一次只一个模块负责人写canonical contracts，其他模型提出差异而不并行重写。
